# Preregistered ablation of P3IF source navigation

This experiment follows the [citation and effort comparison](citation-effort-results.md), where the P3IF workflow and stable-ID diff both reached the accuracy ceiling and differed in effort. The new comparison holds the P3IF audit and transition report fixed and varies its source navigation. It uses 16 fresh revision pairs from ScienceResearch and MathEducation. The [case specification](../manuscript/navigation-case-spec.json) and [answer manifest](../manuscript/navigation-case-manifest.json) freeze declarations, context questions, raw sources, and exact citation answers.

Four fresh model sessions each review eight cases in two periods. Every case appears once per arm, at the same position and period in two different sessions. Two sessions receive navigation first and two receive the other arm first. Each period contains two cases from each domain. Sessions receive their assigned packet without previous conversation, assignment labels, the answer key, or other packets. They can recognize whether navigation pointers are populated.

Both arms receive identical snapshots, citation questions, lookups, reader code, and report fields. The navigation condition fills `changes.source_pointers` with pointers for changed declarations on each side and explicit nulls for absent declarations. The control sets that array to empty. Auditing and transition fields are otherwise identical. The reader offers the same commands in both arms, including record search and exact extraction for a chosen pointer. Contextual citations on no-change controls use the same reader in both arms.

Publish these methods, the packet builder and scorer, and the [packet commitment](../manuscript/navigation-ablation-commitment.json) before delivery. Independently check every file digest and compare both reports for each case after removing only the navigation array. Session folders bind the packets and action logs. Delivered materials omit condition labels.

## Outcomes

Use a single CPython 3.12.16 runtime and serial reader operations. For every question, submit both roles once. Exact correctness requires matching raw source SHA-256, JSON Pointer, half-open Unicode and UTF-8 ranges, and the full quotation SHA-256. A declared absent side requires explicit null. Missing, malformed, and incorrect sides remain in the accuracy denominator. Report complete cases, correctness for present and absent sides, and matched accuracy counts.

The primary effort measure is the number of logged case resource opens, finds, searches, and citation extractions, including logged failures and repeated operations. A syntax failure before the reader parses an action is outside the ledger. Case start, schedule, and submit operations are excluded. Secondary elapsed time uses the shared monotonic clock from the first evidence operation through the recorded successful submission. Bind the submission to its original bytes. Report each arm and domain, matched medians for navigation minus control, and the number of matched cases with valid evidence in both arms. Show reader action totals and the declared no-change controls separately as descriptive checks. Elapsed time includes model and tool delays. The fixed revisions and four sessions define the scope of the comparison.

Score after all sessions finish. Preserve all original answer files and action ledgers, including failures and procedural deviations. Publish the ledger, assignment, and score files after review. Verify that the packet inventory and score can be regenerated byte-for-byte and that all submitted actions occurred after registration.

## Regenerate the packets

From a checkout with P3IF installed, run the following commands into a fresh directory.

```sh
trial=$(mktemp -d)
python scripts/citation_cases.py "$trial/cases" --specification docs/manuscript/navigation-case-spec.json
cmp "$trial/cases/case-manifest.json" docs/manuscript/navigation-case-manifest.json
python scripts/navigation_ablation_packets.py "$trial/cases" "$trial/packets" --manifest docs/manuscript/navigation-case-manifest.json
```

Compare the generated `packet-manifest.json` SHA-256 with the commitment before delivery.
